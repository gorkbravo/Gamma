What it is

Scope, boundaries and the things people most often assume.

Can Gamma place trades?

No, and it is not a setting. Gamma places no orders, executes no strategies, and does no rebalancing. The read-only contract is exposed by the API itself at /system/read-only-boundary, which covers both the TWS API operator lock and the app-side refusal to execute.

That boundary is also why the Strategy Lab Script mode runs only in an isolated ephemeral runtime with no network, no local files, no credentials, no Gamma API access, and no broker or wallet authority.

Is this investment advice?

No. Gamma is research software. It helps you inspect data, compare signals and see the arithmetic behind a number. It does not produce recommendations, and its interpretive layers — macro divergence and coherence labels, commodity roll and spread heuristics, prediction-market research rank, crypto screen scores — are explicitly Gamma heuristics, labelled as such on screen.

Is there a hosted version, or an installer?

No to both. There is no SaaS, no account, no telemetry, and no released binary today. The distribution path is cloning the repository and running it locally. That is deliberate for a tool that holds broker credentials and provider keys, but it does mean setup is a real step rather than a download.

Who is it for?

Someone comfortable with a terminal, a Python virtual environment and their own broker session, who wants cross-domain research in one place and wants to see how each number was produced. If you want a one-click app with a managed backend, this is not that.

Data and providers

What is live, what is optional, and what is not built yet.

Do I need an Interactive Brokers account?

Not to run Gamma. You need one for the Portfolio tab, live IV surfaces and options Greeks, IBKR-built futures curves, and FX history. Everything else works without a broker: Macro, Prediction Markets, Crypto, Fundamentals, Commodities on EIA, Sealanes, Copilot and Equity Research.

The live path is Trader Workstation. IB Gateway is not supported yet.

How many API keys do I actually need?

Zero to start. Yahoo Finance, Polymarket, Kalshi, CoinGecko, GeckoTerminal, US Treasury and SEC EDGAR all work without one. FRED is the highest-value free key because it drives all of Macro. EIA, US Census, AISstream and OpenAI each unlock one specific surface.

The keys page lists every provider, the signup link, and exactly what degrades without it →

Where are my keys stored, and can the frontend see them?

In a local .env read by the FastAPI process. No key is compiled into the frontend bundle or sent to the browser. The AISstream websocket is proxied through the backend specifically so the credential stays server-side. Provider exception text and credentials are also kept out of user-facing warning messages.

Why does a tab show sample data when I configured a real provider?

Because Gamma refuses to hide a provider failure. When a live path is configured but unavailable, it keeps the sample or cached payload and returns an explicit coverage warning with a Sample label. Check the provenance panel on that surface. It names the provider, retrieval time, origin and freshness.

Common causes: TWS not running, missing market-data entitlements, a rate-limited Yahoo circuit breaker still cooling down, or COMMODITIES_PROVIDER still set to sample.

Sealanes shows zero vessels. Is it broken?

Usually not. AISstream has real regional coverage gaps, and Gamma only subscribes to your configured bounding boxes above a zoom threshold, for a short sampling window. An empty count is most often genuine absence of coverage in that box at that moment.

Sealanes is also an honest prototype: Live Map is the strongest mode, while chokepoint counts, trade-flow proxies, fleet context and event replay are limited by partial live AIS and the absence of durable historical AIS, port-call and cargo data. Risk, sanctions and dark-activity labels are deliberately out of scope until the methodology holds up.

What about the BLS, ECB, Eurostat and IMF providers I see in .env?

Reserved slots. Those adapters are not written. They appear in Gamma's provider-capability metadata as Planned so the roadmap is legible, and the surfaces that would use them show curated placeholders labelled as placeholders. Setting those keys today does nothing.

Analytics and limits

What the maths does, and where it stops.

How trustworthy are the risk numbers?

The engine is history-based and linear in spirit: historical and parametric VaR, CVaR, Monte Carlo under Gaussian draws or historical bootstrap, contribution-to-risk. It is not a full nonlinear scenario engine, and Monte Carlo v1 supports long-only, unlevered books only.

When only part of the book has usable history, the headline total VaR is a scaled estimate. Gamma says so, and the coverage diagnostic names every excluded asset rather than quietly dropping it.

Can I model a short or a long-short book?

Not yet. Synthetic research scopes and the Risk engine currently work on long-only weights; negative weights are dropped rather than modelled, and there is no pair or long-short construct. Treat Gamma's scope analysis as a long-book tool for now.

Are the Greeks and payoff matrices broker-grade?

No. Gamma preserves provider Greeks when IBKR supplies them, and derives its own from provider or solved IV using zero-rate, zero-dividend Black-Scholes assumptions otherwise. The panel tells you which you are looking at. The implied-probability view is a local lognormal density proxy from the fitted IV grid, not a vendor risk-neutral-density feed.

The payoff matrix marks selected legs to model values across remaining days. It is research math, and implies no order routing or broker valuation authority.

Is the Macro divergence score a model?

No, and Gamma is direct about it. Each themed signal is a clamped, scaled version of the series' move over the active timeframe; divergence is the strongest positive signal minus the strongest negative one. Coherence and lead/lag come from asking when each supportive series reached roughly 60% of its current move.

It is a transparent heuristic for structuring attention. It is not a statistical factor model, and event lead/lag is especially noisy on monthly or quarterly series.

Which surfaces are still first-pass or paused?

Being explicit about maturity, since the tab bar does not distinguish:

  • Fundamentals: complete for the current pass; strongest on US SEC filers.
  • Prediction Markets: first pass complete; calibration coverage is still thin and venue-dependent.
  • Commodities: first pass; deeper vendor-grade historical curve storage is future work.
  • Options / IV: a usable volatility lab, not a full options analytics suite; historical IV and skew persistence remain open.
  • Macro and Crypto: paused at their first-pass checkpoints.
  • Sealanes: a paused prototype with uneven analytical depth.

Running it

Practical failure modes.

Every API request comes back 401.

The backend requires a session token on every route except /health. GAMMA_SESSION_TOKEN on the backend and VITE_GAMMA_SESSION_TOKEN on the frontend must be the same string, and the frontend reads it at dev-server start, so restart Vite after changing it.

What operating systems does it run on?

The stack is cross-platform (FastAPI, Svelte, Tauri) and development happens on Windows, which is why the documented commands are PowerShell. On macOS or Linux the equivalents are the usual python3 -m venv, source .venv/bin/activate and export VAR=value.

Can I use it offline?

Yes. MOCK_DATA=true runs every surface against bundled sample providers with no network at all, and the mock state is always labelled Mock. It is how the screenshots on this site were captured, and the honest way to evaluate the app before wiring up credentials.

Is there a licence?

The repository does not currently carry a LICENSE file, which means default copyright applies and no reuse rights are granted. If you want to build on it, open an issue and ask.
